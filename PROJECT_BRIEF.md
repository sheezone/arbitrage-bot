# Арбитражный Telegram-бот — полный технический брифинг проекта

## Цель проекта

Telegram-бот, который непрерывно сравнивает коэффициенты одного и того же матча (киберспорт: CS2/Dota2/LoL, и теннис) у разных букмекерских контор, находит арбитражные ситуации ("вилки") — когда сумма обратных коэффициентов на все исходы < 1, что даёт гарантированную прибыль независимо от результата, — и присылает пользователю уведомление с раскладкой, сколько на что ставить при заданном банкролле.

Бот **не делает ставки сам** и не хранит логины/пароли от букмекерских контор — только считает и уведомляет. Это осознанное ограничение: хранение чужих учётных данных для автоматической простановки ставок — то, что бот не должен делать.

Расположение проекта: `E:\букмекерки` (Windows). Telegram-бот: `@Lineyka111_bot`.

## Архитектура

```
bot/
  main.py                  — entrypoint: создаёт Dispatcher, запускает polling + monitor task
  config.py                 — чтение .env
  core/
    arbitrage.py             — чистая математика: OutcomeOdds, ArbitrageResult, calc_arbitrage(), calc_stakes()
    reconcile.py              — сопоставление одного и того же матча между разными источниками
    monitor.py                 — фоновый цикл: опрашивает все источники, сопоставляет, считает вилки, уведомляет
    state.py                    — LatestState: кэш последнего результата для мгновенного ответа на "Искать сейчас"
  providers/
    base.py                  — интерфейс OddsProvider.fetch_quotes(games) -> list[SourceQuote]
    models.py                 — Fixture, BookmakerQuote, SourceQuote (общая валюта между источниками)
    oddspapi.py                — легальный платный/бесплатный агрегатор (oddspapi.io)
    fonbet.py, pari.py          — скрапинг Fonbet и PARI (используют общий _line_platform.py)
    marathon.py                — скрапинг Marathonbet (SSR HTML, без JS/капчи)
    _line_platform.py           — общий парсер для Fonbet/PARI (они на одном движке)
  handlers/
    commands.py               — весь UI бота: одно редактируемое сообщение (inline-кнопки), без ленты сообщений
    states.py                  — aiogram FSM states (ожидание ввода банкролла/порога)
  db/
    schema.sql, repository.py  — sqlite: users (банкролл/порог/игры/статус/id сообщения-панели), seen_opportunities (дедуп уведомлений)
tests/                        — pytest, покрывает arbitrage.py, reconcile.py, marathon.py (без сети/токенов)
```

## Ключевая математика (bot/core/arbitrage.py)

- Для каждого исхода матча находим максимальный коэффициент среди всех источников/букмекеров.
- `arb_ratio = sum(1/best_odds_i)`. Если `arb_ratio < 1` → вилка. `profit_pct = (1/arb_ratio - 1) * 100`.
- `calc_stakes(bankroll, best_odds)`: ставка на каждый исход пропорциональна `1/odds_i`, так что выплата одинакова независимо от исхода.

## Источники коэффициентов (4 штуки, опрашиваются параллельно каждый цикл)

1. **OddsPapi** (`oddspapi.io`) — легальный документированный API. Отдаёт котировки bet365, 1xbet, 22bet и др. для cs2/dota2/lol/tennis.
   - **Важное ограничение**: бесплатный тариф — квота 250 запросов (не в минуту, а всего/за период). Оптимизировано: батч-эндпоинт `/v4/odds-by-tournaments` (до 5 турниров за 1 запрос на 1 букмекера) вместо запроса на каждый матч. Список букмекеров сокращён до `["bet365", "1xbet"]` чтобы не жечь квоту. Теннис (у него турниров больше, чем во всём киберспорте вместе) троттлится отдельно — не чаще раза в 10 минут, использует кэш между обновлениями.
   - Реальная схема API (marketId=171 — "Winner" moneyline market, формула marketId = sportId*10+1, outcome1Id=marketId, outcome2Id=marketId+1) была реверс-инжинирена вживую с реальным ключом — в блогах/маркетинге провайдера это не задокументировано.
   - Квота истощается легко (в этой сессии несколько раз ловили 429 просто от тестирования).

2. **Fonbet** и **PARI** (`bot/providers/fonbet.py`, `pari.py`) — недокументированные публичные JSON-эндпоинты (`.../events/listBase?lang=ru&scopeMarket=...`), найдены наблюдением за сетевым трафиком сайтов в браузере. Без CAPTCHA, без авторизации.
   - **Критическая находка**: Fonbet и PARI работают на одном трейдинг-движке — на 14 живых CS2-матчах коэффициенты и даже внутренние ID событий совпали побитово. Значит, вилка между именно Fonbet и PARI невозможна в принципе — только против OddsPapi/Marathon.
   - Общий парсер в `_line_platform.py`. Матчи с фактором "ничья" (Bo2-серии) сознательно пропускаются — включение их как 2-way рынка давало математически невозможные "вилки" (баг, не реальная вилка).
   - Каждый цикл скачивают ~7MB дамп всей линии — поэтому опрос не стоит делать слишком частым (сейчас `POLL_INTERVAL_SECONDS=30` по явному запросу пользователя, хотя изначально ставил 120-150 из вежливости к их инфраструктуре).

3. **Marathon** (`marathonbet.ru`, `bot/providers/marathon.py`) — **не SPA**, обычный server-rendered HTML. Простой `httpx.get()` без JS и без капчи уже возвращает таблицу коэффициентов. Каждое событие — `<div data-event-eventid="..." data-event-path="...">`, внутри скрытый `<td data-json='{"teamNames": [...]}'>` и ровно два `<td data-market-type="RESULT_2WAY" data-sel='{"epr": "1.51"}'>` — это и есть 2-way коэффициенты. Для киберспорта конкретная игра (cs2/dota2/lol) зашита в URL-путь события (`e-Sports/Dota+2/...`). Известный пробел: время начала матча не извлекается (пусто), сопоставление между источниками для Marathon опирается только на fuzzy-совпадение имён команд.

### Проверенные, но не подключённые источники
- **Winline** — реальный API есть, но только для иконок/видео-виджетов; сама линия коэффициентов идёт через WebSocket, недоступный для используемых инструментов наблюдения.
- **Лига Ставок** — закрыта капчей Qrator (proof-of-work + CAPTCHA). Не обходил принципиально.
- **BetBoom** — признаки антибот-защиты (похоже на Group-IB fingerprinting). Не обходил.
- **BetCity, OlimpBet, Zenit, Bet-M, Tennisi, СпортБет, 24bet, Мелбет, Baltbet, Bettery** — частично прощупаны (см. историю сессии), не все доведены до готовых парсеров. Baltbet выглядел многообещающе (тоже SSR HTML с data-event атрибутами, как Marathon) — следующий кандидат.

## Сопоставление матчей между источниками (bot/core/reconcile.py)

Поскольку у каждого источника свои названия команд/игроков (регистр, пунктуация, иногда кириллица vs латиница для тенниса), матчи группируются так:
1. Бакет по (`game`, округлённое до 30 минут время начала).
2. Внутри бакета — fuzzy-сравнение (SequenceMatcher, порог 0.72) пары нормализованных названий команд, с транслитерацией кириллицы в латиницу перед сравнением (простая посимвольная таблица, не идеальная — например, "Джокович" транслитерируется как "dzhokovich", а не как принятое английское "djokovic", поэтому нужен именно fuzzy-match, а не точное совпадение).

**Известное ограничение**: не идеальный fuzzy-match — сильно отличающиеся сокращения имён могут не склеиться. Marathon дополнительно не имеет времени начала матча (пусто), так что для него сопоставление держится только на похожести имён.

## UI бота (bot/handlers/commands.py)

По явному запросу пользователя UI не оставляет "ленту" сообщений — вся навигация происходит через **редактирование одного и того же сообщения** (inline-кнопки, `bot.edit_message_text`), а не отправку новых. Только `/start` создаёт (или пересоздаёт) это сообщение. Ответы на текстовый ввод (банкролл/порог прибыли) — временное сообщение пользователя удаляется сразу после обработки (`message.delete()`), а панель-сообщение просто обновляется.

Категории в UI объединены: CS2/Dota2/LoL показываются одной кнопкой «🎮 Киберспорт» (хотя внутри учитываются как отдельные игры), плюс отдельно «🎾 Теннис».

Кнопка **«🔍 Искать сейчас»** не делает новый сетевой запрос — читает `LatestState` (кэш последнего цикла фонового мониторинга), поэтому отвечает мгновенно.

## База данных

sqlite, файл `arbitrage_bot.sqlite3`. Таблица `users`: chat_id, bankroll, min_profit_pct, watched_games (csv), is_active, menu_message_id (для редактируемого UI). Таблица `seen_opportunities`: дедуп уведомлений (не слать одно и то же повторно).

## Текущий статус деплоя (на момент написания)

- Бот работает **локально на Windows-компьютере пользователя** (не 24/7).
- Куплен VPS: **VDSina**, 1 CPU/1GB RAM/10GB NVMe, Ubuntu 26.04, IP `138.16.171.181`, хостнейм `v3201295.hosted-by-vdsina.ru`.
- **Важная проблема**: исходящий SSH (порт 22) с компьютера пользователя обрывается сразу после TCP-хендшейка (`kex_exchange_identification: Connection closed by remote host`) — причём это происходит **и к VPS (порты 22 и 2222), и к github.com** одинаково. Значит, дело не в конкретном сервере, а похоже на блокировку SSH-протокола на уровне провайдера/сети пользователя (характерно для российских провайдеров с DPI). Антивируса/файрвола с фильтрацией у пользователя, по его словам, нет.
- **Обходной план (в процессе)**: 
  1. Код запушен в публичный репозиторий `https://github.com/sheezone/arbitrage-bot` — через HTTPS (порт 443, не блокируется), пуш пользователь делает сам из своего терминала (Git Credential Manager сам открывает браузер для входа).
  2. На сервере — доступ **только через веб-консоль VDSina в браузере** (не SSH), там `git clone` (публичный репозиторий, авторизация не нужна).
  3. Дальше в этой же консоли: установка Python/зависимостей, `.env` с секретами (вписывается вручную, не через git), systemd-сервис для автозапуска/перезапуска.
- **Важный практический урок**: длинные однострочные команды, вставляемые в веб-консоль VDSina, иногда теряют символы при вставке (наблюдали минимум дважды — команда с `mkdir && echo ... && chmod` не записалась целиком). Рабочее решение — разбивать на короткие однострочные команды и проверять результат (`cat`/`wc -c`) после каждого шага, а не доверять длинным цепочкам через `&&`.
- SSH-ключи сгенерированы (не пригодились из-за блокировки): `~/.ssh/bukmekerki_vps` (для сервера), `~/.ssh/bukmekerki_github` (для GitHub).

## Известные компромиссы / вещи, которые стоит держать в голове

- Fonbet и PARI никогда не дадут вилку между собой (один движок) — реальные вилки нужно искать против OddsPapi/Marathon.
- Скрапинг Fonbet/PARI/Marathon — недокументированные эндпоинты/структура HTML, могут измениться без предупреждения.
- OddsPapi бесплатная квота (250) — узкое место, особенно с теннисом.
- Арбитражные ставки не запрещены законом РФ, но большинство букмекеров запрещают их в своих правилах (ToS) и может лимитировать/блокировать аккаунты.
